# Agent workflow and context changes

The default model and reasoning setting are unchanged by this work.

- `lavender_apply_edits` applies up to 100 non-overlapping edits to one file. All ranges use the original file's one-based, inclusive coordinates. An empty range (`endLine = startLine - 1`) inserts. The tool verifies the original hash, rejects overlaps, preserves encoding/newlines, makes one backup and atomically replaces the file. Its result includes the new hash and per-edit line deltas. Atomicity is per file, not across files.
- `lavender_list_files` provides sorted, paginated path discovery for source, configuration and assets without embedding them. It excludes generated/dependency folders and links. Query is a substring, not a glob.
- Read tracking is scoped to one agent run. A case-insensitive path dictionary contains file hashes and sorted, non-overlapping retained intervals. Binary search finds overlapping ranges; only gaps are included in subsequent tool context. References point to source that is actually retained in the current request. The tool still reads disk to verify the whole-file hash; this saves context, not disk I/O or the model call that requested the tool.
- Any successful edit/move/delete or newly observed hash invalidates the affected file's old readings. We deliberately discard the whole file's coverage instead of shifting old snapshots across edits. Newly written source is not automatically considered verified. Unchanged files keep their coverage.
- Oversized source results return a request to use a smaller range rather than falsely marking truncated source as seen. Retained source has a 120,000-character budget; eviction also removes coverage. This is not a total conversation-token limit.
- Coverage is invalidated immediately; historical context is rewritten at shared checkpoints every eight tool rounds, or sooner under source-size pressure (120,000 retained characters or 96,000 pending retirement characters). Latest successful hashes supersede old snapshots between checkpoints. This reduces prefix churn; actual cache hit rates/cost still need measurement.
- Completed edit exchanges older than two rounds are removed as complete call/result pairs at checkpoints and replaced by a separate outcome summary. Executable argument fields are NEVER rewritten with placeholder source. Successful, failed and blocked outcomes remain distinguished, and original execution records remain in the audit with existing truncation limits.
- Write guards reject Lavender context/truncation markers before MCP execution and again inside the filesystem writer. Required fields and basic JSON types are validated before MCP parameter binding. An omitted edit hash can be filled from a successful read/write already observed in this run; the filesystem still verifies it against disk. No hash is invented or fetched automatically to bypass a conflict.
- Adjacent replacement calls from one model response can be combined if they explicitly use the same path/hash and non-overlapping original ranges. Insertions, missing hashes, overlapping ranges and intervening tool calls are kept separate. One atomic batch executes; each original call receives its confirmed outcome. This reduces tool executions; the prompt also asks the model to group known changes to reduce model round trips.
- Tool image previews are retired at the same compaction checkpoints. Every new preview is retained for at least one subsequent model request. Metadata remains available; the agent can inspect again. Keeping previews longer is an intentional tradeoff to reduce cache invalidations.
- Diagnostics use a separate fresh Roslyn workspace for each changed revision, without embeddings. Repeated unchanged requests reuse compiler results. Fingerprints include source/configuration, restore outputs, discovered document/reference dependencies, and ancestor build configuration. Workspace warnings are returned. This is compiler analysis, not an actual build or runtime test. Incremental workspace refresh is a later performance optimization; custom MSBuild inputs outside the discovered paths remain a limitation.
- Git diff checks repository availability before invoking diff. Identical recent failed diagnostics/Git requests are suppressed briefly; edits clear that failure cache. The agent prompt encourages discovery, coherent batch edits and one verification pass.

Telemetry adds `read_range_cache`, `edit_batch`, `context_compacted`, `edit_context_compacted`, `diagnostics_snapshot`, and `tool_repeat_blocked` events. `tools/api_usage_summary.py --workflow` adds these totals plus recovered hashes, rejected arguments, combined tool calls and retired edit exchanges. API totals now explicitly show uncached input tokens and cache-hit percentage. Character savings are local payload estimates, not provider-reported token or cost savings. Compare actual provider token usage on the next user-run task.

No builds, tests, sample games or model API calls were run while implementing these changes, per the user's instruction.
